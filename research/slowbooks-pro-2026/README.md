# SlowBooks Pro 2026 — Complete Feature Inventory

**Subject:** [VonHoltenCodes/SlowBooks-Pro-2026](https://github.com/VonHoltenCodes/SlowBooks-Pro-2026), commit `486c64b` — version 2.18.1, released 2026-09-27  
**Compiled:** 2026-09-29, from a read of the source code — routes, services, models, UI scripts, PDF templates, packaging and CI — cross-checked against the project's own documentation.  
**Layout:** this index, nine section files and three appendices. Every section follows the same pattern — an overview, one subsection per feature area ending in its key source files, a table of the section's API endpoints, and the notes, gaps and discrepancies found while verifying it.

> **How this was verified.** Every section was written from the code, not from the README or marketing copy. Where the docs and the code disagree, the entry describes what the code does, and the difference is recorded under *Notes, gaps & discrepancies* at the end of that section. The most surprising claims were then re-checked by hand against the source. Tax, payroll and compliance behaviour is described as implemented — the project itself labels its tax figures approximate — and nothing here is tax or legal advice.

## What stands out

- **Tamper-evident payroll tax forms** — W-2, W-3, 940 and 941 PDFs from the payroll forms screen carry a SHA-256 content hash and an audit ID in the footer, recorded in `document_audits` ([§4](04-payroll-hr.md)).
- **Agent-operable** — every install serves a self-documenting REST API of 546 operations; API tokens carry a role, are stored only as hashes and are attributed in the audit log ([§8](08-platform-security-administration.md), Appendix A).
- **Bring-your-own-AI** — eight providers (Anthropic, xAI, Groq, Cloudflare Workers AI, a self-hosted Cloudflare Worker gateway, OpenAI, Google Gemini, any OpenAI-compatible endpoint), keys encrypted at rest, SSRF and MITM guards, eleven one-shot curated analyses ([§5](05-reports-dashboard-analytics-ai.md)).
- **Payroll for every state plus DC** — dedicated engines for WA, CA, NY and OR, table-driven withholding for the other 47 jurisdictions, reciprocity, state paid-leave and disability premiums, CCPA garnishment limits, and a rule-driven benefits engine with dated rates and tiered 401(k) matching ([§4](04-payroll-hr.md)).
- **Banking where the register is the ledger** — imported statement lines wait in a review queue and are matched to postings the ledger already has; SimpleFIN bank feeds with a hardened connection and "Fetch older history" ([§3](03-general-ledger-banking.md)).
- **Receipt scanning without the cloud** — Apple Vision on macOS, Windows OCR on Windows, Tesseract on Linux; deterministic parsing, a box-to-fix canvas and a per-merchant layout memory ([§2](02-purchasing-payables-inventory.md)).
- **Full nonprofit mode** — one switch swaps 48 terms on every screen and report; funds with donor restrictions, functional allocation, Statement of Activities / Financial Position / Functional Expenses (Form 990 Part IX columns), IRS Pub. 1771 receipts and giving statements ([§6](06-nonprofit-jobs-job-costing.md)).
- **Construction-grade job costing** — cost codes (CSI MasterFormat loader), cost types with burden, equipment and mileage, budgets seeded from estimates, committed cost from purchase orders, and real payroll burden spread onto jobs ([§6](06-nonprofit-jobs-job-costing.md)).
- **Leaving other software** — QuickBooks Desktop (IIF), QuickBooks Online (OAuth), Xero, MYOB, Sage 50, Wave, Zoho Books, GnuCash and hledger, each gated by a dry run ([§7](07-import-export-migration.md)).
- **Guard rails everywhere** — closing-date enforcement with a lockout on the override password, control accounts that can be renamed but never renumbered, $0.00 "save anyway?" confirmations, voids that post reversing entries and never delete ([§1](01-sales-accounts-receivable.md)–[§3](03-general-ledger-banking.md)).
- **Accessibility as a feature** — WCAG 2.1 AA as the target, labelled controls, live-region notifications, dialog focus management, and every generated PDF tagged PDF/UA-1 ([§9](09-ui-desktop-deployment-engineering.md)).

## What verification turned up

Every section ends with its own *Notes, gaps & discrepancies*. These are the findings most worth knowing before relying on the app; those marked **(re-checked)** were confirmed by hand against the source after the section was written.

- **Security — password hash in the audit log (re-checked).** Audit redaction matches only a column named `password_hash`, but the operator's Argon2id hash lives in the settings row `auth_password_hash`, so it is copied into `audit_log`, which admins and bookkeepers can read through `/api/audit` ([§8](08-platform-security-administration.md)).
- **Employee portal pay-stub download (re-checked).** The portal's "Download PDF" link points at the admin-only `/api/payroll/{run}/paystub/{stub}`, so an employee without an administrator session gets 401 ([§4](04-payroll-hr.md)).
- **Payroll set-up traps (re-checked).** A PTO policy saved with the form's default maximum balance of 0 caps the bank at zero hours, and the admin direct-deposit form sends deposit types (`fixed_amount`, `percentage`) that the API rejects ([§4](04-payroll-hr.md)).
- **Pay runs can't be voided or deleted.** A `void` status exists but nothing sets it; draft runs count toward year-to-date tax bases and lock the time entries they used ([§4](04-payroll-hr.md)).
- **Audit hashes cover less than the README says.** Only the four `/api/payroll/forms/*/pdf` renderers write them — not `/api/tax-forms/*`, pay stubs or the 1099-NEC/1096 — and the rows are independent hashes, not a chain ([§4](04-payroll-hr.md), [§8](08-platform-security-administration.md)).
- **Recurring invoices ignore "Due on Receipt" (re-checked).** The recurring service parses only "Net N", so every other term becomes +30 days ([§1](01-sales-accounts-receivable.md)).
- **Online checkout always charges USD (re-checked).** Stripe, PayPal and Square requests hard-code the currency ([§1](01-sales-accounts-receivable.md)).
- **QuickBooks Online booleans (re-checked).** The importer reads fields as `value or default`, so `Taxable=false` and `Active=false` import as true for customers, vendors and items ([§7](07-import-export-migration.md)).
- **IIF gaps (re-checked in part).** `CCARD` accounts aren't mapped and import as expense; customer addresses in `BADDR`/`SADDR` aren't read; classes survive re-import only on bills and deposits ([§7](07-import-export-migration.md)).
- **Bills can't be edited (re-checked)** — only voided and re-entered — and inventory adjustments post to cost of goods sold because account 5900 is never created, whatever the code comment says **(re-checked)** ([§2](02-purchasing-payables-inventory.md), [§3](03-general-ledger-banking.md)).
- **The boot-time wiring check can't stop a boot (re-checked).** The README says drift between the JavaScript and the routes "fails the boot", but `docker-entrypoint.sh` runs the check as `pytest … | tail -5` without `pipefail`, so the `if` only ever sees `tail`'s exit status ([§9](09-ui-desktop-deployment-engineering.md)).
- **Accrual basis only.** No report offers a cash basis; the Analytics page instead counts only fully paid invoices and bills ([§5](05-reports-dashboard-analytics-ai.md)).
- **Docs lag the code.** Counts and endpoint tables in `docs/features.md`, `SECURITY.md` and `docs/hipaa-compliance.md` predate multi-user roles and several releases; each section lists the specific mismatches.
